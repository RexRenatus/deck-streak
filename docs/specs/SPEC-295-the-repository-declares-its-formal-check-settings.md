# SPEC-295: the repository declares its formal-check settings in one file, and decides it is judged against the development branch

- **Wave:** W4. **Issue:** #468. **Context(s):** `repo` (`config/`, `scripts/tests/` and `docs/`).
- **Decided by:** ADR-295 (this SPEC's own: the repository carries the file, judged against the
  development branch, and what it was chosen against).
- **Status:** built. It holds `docs/red-first/SPEC-295.md`.

## 1. The problem, measured

- **The formal checker refuses this tree today.** Run over the development branch's work tree, the
  checker stops at once and reports that the settings file is absent at the head commit. No property
  is selected, no TLA+ model and no Lean statement is ever examined, and a delivery whose surface
  owes a model can only write "required, not checkable" and stop before its push. Measured on the
  development branch at `73b8d6b` before this delivery: `git ls-tree -r --name-only HEAD` lists no
  path that names formal, so the file the checker reads first is not there (#468).
- **The checker reads a fixed set of fields and no others.** They are the search depth `k`; the
  budgets in seconds for a TLA+ run, a Lean run and one entry, with a map of per-entry budgets; the
  list of axioms a Lean proof may use; the repository-relative path of the owner's trust file; and
  the slot the model checker waits for, its capacity and its wait in seconds. A field outside that
  set is read by nothing.
- **The checker judges against a base commit it is given.** The repository's release branch is far
  behind its development branch, so a check that names the release branch as its base would judge
  every change since the last release, not the delivery (#468).

## 2. Requirements

- **R1.** `config/formal.json` holds exactly these fields and values, pretty-printed with one field
  per line: `k` 20; `budgets` with `tla_seconds` 300, `lean_seconds` 600, `entry_seconds` 300 and
  `entries` empty; `axioms` `propext`, `Classical.choice`, `Quot.sound`; `owner_signers`
  `config/owner-allowed-signers`; `tlc_slot` with `capacity` 1 and `wait_seconds` 1800. It carries
  no other field.
- **R2.** Formal checks are judged against the development branch's live commit, never against the
  release branch.
- **R3.** An entry's `cites` names a real issue or pull request of this repository as `#<n>`, and
  its `covers` names `.rs`, `.py` or `.sh` spans only. A web surface or a workflow file cannot be
  covered yet: a delivery that touches one names it in its report as not coverable.
- **R4.** A mutation row removed while its target file stays is a weakening. It needs the owner's
  signed ruling, by a key the allowed-signers file holds at the merge-base. That file is not part of
  this delivery: it lands in a separate, owner-signed change, and until then it is absent and holds
  no key.
- **R5.** `k`, the axioms and the signers path are ratcheted once committed: a change to `k`, an
  added axiom or a changed signers path is itself a weakening.
- **R6.** `config/formal.json` names the formal checker's toolchain by its identity: a `toolchain`
  object whose one field `identity` is 64 lowercase hex digits (#504). The formal check then uses the
  checker's own tool pin when the two identities are equal, refuses a checker built with another pin
  as drift, and refuses a tree that also commits a pin file. No pin file is committed.

are rules of the review of a delivery and R4 and R5 are rules of the checker: this delivery states
them and the test does not judge them.

## 5. What this does NOT do

- It adds no `formal/` directory, no TLA+ model and no Lean statement: the first entry is a later
  delivery (#468).
- It adds no `config/owner-allowed-signers` file: the trust file is the owner's own signed change,
  so it holds no key here (#468).
- It adds no toolchain pin and changes no CI job or box wiring: running a model needs the checker's
  toolchain, which is not this delivery's to supply (#468).
- It changes no Rust, no web surface and no existing test (#468).

## 6. Risks

- **R4 is a practice change.** Retiring or renaming a mutation row whose target stays becomes an
  act that needs the owner's signed ruling. Over the development branch's whole history no merged
  pull request removed such a row, so the measured cost so far is nil (ADR-295).
- **`k` is fixed at first commit.** A later change to it is a weakening, so the value is the
  owner's to settle before this file merges.
- **A field the checker does not read is dead text.** R1 lists the fields the checker reads and no
  other, and A1 and A3 refuse an extra field.

## 7. The mutation rows

It adds no mutation-row band: the change is a configuration file, a test file and documents, and the
test is a guard over data with no production code to mutate (#468).

## 9. Amendment, 2026-09-30: every value type a kind refuses is planted, an integral float included

Issue #488, a review of #468 and #470. Sections 1 to 8 stand as written and this section only adds
to them. Section 7 says this SPEC adds no mutation-row band, and that is superseded here: it now
has one, `S29500` to `S29599`, in `scripts/mutation-rows.d/S29500-S29599.json`, because the test
file holds the reader the criteria judge, and a mutant of that reader is a change to a file with
code to mutate. A row's target is `scripts/tests/test_formal_config.py` and its killer is that
module's own test.

**What the review found.** The reader's kinds are tested against one planted value of each JSON
type they refuse, and three inputs were outside those plants: an integral float such as `20.0`
where a positive integer is required, and a `null` or a float as a value inside an integer map.
The reader already refuses each, so no test was red. But a mutant of the reader that admits any of
them, that admits a string, an array or an object as a map value, or that judges only the first or
only the last value of a map, survived every test. Measured on the development branch's test:
nine such mutants survived and eight other mutants of the same arms were already killed.

**The class.** For every field kind the reader judges, the object kind included at every object
level, and for every element kind inside a container kind, a map or a list, each JSON value type
the kind does not admit is planted at every field of that kind, and the reader refuses each by the
name of the kind's own arm: the refusal names its field and its kind, and the test asserts both.
An integral float is one of those types wherever an integer is required, because Python reads
`20.0` as a float where the document spells an integer. A container's element is planted alone,
after a good value and before one. The population is generated from the field table, the admitted
types, the element kind of each container kind and a good value of each element kind, so a field, a
kind or a container kind added to the table is planted with no edit to a list. The test prints and
asserts the member count per kind and in total: 144 planted value types, of which 21 are of the
object kind at three object levels, 7 of the path kind, 54 of the positive-integer kind, 34 of the
map-of-positive-integers kind and 28 of the list-of-strings kind. Its admission side runs the
reader over seven documents that hold only what the kinds admit (a container holding good values,
each optional field absent, each optional object level absent), and each is admitted, so a reader
that refuses a valid document turns a test red. The generated faults of the third criterion hold
158 members.

## 11. Amendment, 2026-09-30: the file names the checker's toolchain by identity

Issue #504. Sections 1 to 10 stand as written and this section only adds to them. Section 5 says
this SPEC adds no toolchain pin, and that stays true: the delivery commits no pin file. The formal
checker now carries its own tool pin and lets a repository name that pin's identity in
`config/formal.json` instead of committing a pin file. Until a tree names it, every TLA+ and Lean
check stops at its tool stage, so no model is ever checked (#504).

**What changes.** R1's table gains one field, `toolchain`, an object with exactly one key,
`identity`, whose value is 64 lowercase hex digits, and the file is R1's text plus that field, one
field per line. The checker refuses the field whole when it is not such an object, so a mistyped
digest never reads as no identity named. A named identity that differs from the checker's own is
drift, and a tree that commits a pin file and names an identity is refused as having two sources
(R6).

**The class.** The test's field table gains a kind for a 64-digit lowercase hex string, and every
generated plant follows from the table with no list edited by hand: the extra key beside
`identity` and the non-object `toolchain` come from the object-level plants, and every JSON value
type the kind does not admit comes from the admitted-types table. The string values it refuses are
derived from the declared digest by one edit each: one digit short, one digit long, an uppercase
digit, a non-hex digit, an empty string and a trailing newline. The count of the third criterion's
generated faults grows from 158 to 180 and the fourth criterion's planted value types from 144 to
158, so no plant is dropped.

**Not done here.** It commits no pin file and no `formal/` directory, and it changes no CI job
(#504). It adds no mutation-row band: the nine rows of the earlier amendment keep their anchors,
each occurring once (#504).
